## Strategy decisions (read before executing)

1. **Light island, scoped.** The prototype is a warm light theme (`#efe6d3` parchment, dark ink); the dashboard is dark. Everything lives under `.dojo3-stage`, which establishes the light theme + all `--dojo3-*` tokens locally. The rest of the app (login, setup) keeps the dark theme. This is what the previous agent started; continue it.
2. **Raw CSS, not Tailwind, for the glass system.** CLAUDE.md says "Tailwind, no CSS files," but the dispersion-hairline borders (padding-box+border-box gradients), multi-layer shadows, mask-image fades, and stacked backdrop-filters **cannot** be expressed as Tailwind utilities. They already live in `index.css` under `@layer`/scoped rules. This is the sanctioned exception for the redesign. Keep all new prototype CSS in `index.css`, scoped under `.dojo3-stage`.
3. **Reuse markup where possible; restyle in-scope.** The previous agent reuses existing components (`ChatInput`, `.bubble-user/.bubble-assistant`, the real page components) and restyles them within `.dojo3-stage`. Prefer this over rewriting each component, EXCEPT where the prototype's structure is materially different (the composer, the chat message anatomy, the panel card primitives) — there we port the prototype's markup faithfully.
4. **Orb ported verbatim.** The WebGL orb (shader, backdrop generator, state tables, render loop, `dojoOrb` API) is copied essentially unchanged into a React component wrapper, with a proper mount/unmount lifecycle (the prototype leaks its RAF + listeners — see hazards). Do NOT redesign the orb.
5. **Class naming.** Shell structure keeps the `dojo3-` prefix (already established). Prototype's panel-content primitives (`.tile`, `.cards`, `.group`, `.pill`, `.bar`, `.field`, `.switch`, etc.) are ported **scoped under `.dojo3-stage`** so the generic names don't collide with existing dashboard styles.
6. **Load-bearing values must be preserved exactly:** the spring beziers (`cubic-bezier(.30,1.45,.42,1)` composer/fan open; `.30,1.3,.42,1` panel), the interaction timings (fan-reopen 220ms, button→panel 260ms, panel auto-close 60ms, reset disarm 3000ms / "working" 1400ms, presence reveal 1800ms, reply 2200/2600/5400ms, mode-refocus 80ms, mote 650ms), the orb's `--canvas-scale 3.8`, DPR cap 2, `premultipliedAlpha:false` + `gl.disable(BLEND)`.

**Status legend:** `[ ]` todo · `[~]` in progress · `[x]` done · `[!]` blocked/needs decision. Update this file as work proceeds.

## Appendix A — Orb wiring map (call → trigger)

| dojoOrb call | Real trigger |
|---|---|
| `setState('thinking')` | user message sent / model stream begins |
| `setState('speaking')` | TTS playing / voice reply audio |
| `setState('listening')` | mic open (voice session live, unmuted) |
| `setState('idle')` | stream done, voice ended, settled |
| `setEmotion('curious')` / `null` | panel opened / closed |
| `setEmotion('working')` | reset, long operation |
| `setEmotion('success')` | files added, task completed |
| `setEmotion('confused')` | error event |
| `setEmotion('sleepy')` / `null` | presence out / in |
| `pulse()` | fan opened, mote arrives, voice unmute |
| `startTask('image'/'audio'/'song'/'video', {progress})` | generation job start + progress |
| `startTask('compaction')` | memory compaction begins |
| `startTask('dreamer'/'healer')` / `endTask` | agent activates / finishes |
